# Local Codex demo in NemoPal

Build with `pnpm install --frozen-lockfile` and `pnpm build`, then run the existing desktop setup in [setup.md](setup.md). The normal project connection and pairing are still needed to select a project. In that project, open **Codex demo**, choose **Start Codex demo**, select a local folder, and confirm the native disclosure. Send messages in that view; **Manager** returns to the existing project manager conversation.

This starts a new demo-owned Codex thread using the locally installed Codex executable. It does not attach or read an existing active conversation, including the terminal demo. It uses the read-only sandbox and approval policy `never`; this is not a guarantee that Codex or configured tools cannot read outside the folder or use their own permissions. Provider usage may incur costs. Unexpected approval or other server requests are not answered: the session stops and message delivery is reported as unknown. Check before resending. Failed turns and uncertain sends retain the draft; no automatic retry occurs.

While this explicitly started session is active for the selected project, the manager can submit a structured task request automatically. Requests remain pending without such a session. A paired desktop durably claims each request before sending; a lost claim response or interrupted send is not automatically retried. The project conversation shows the request, its status, and any returned Codex activity, labeled untrusted. A claimed request with no confirmed outcome requires checking before any new request; a request whose project epoch or task has changed may remain pending. Source-derived requests and results are withdrawn with their source evidence. The project service stores this activity; it is not an observation or proof that a task is complete.

Manual conversation is held in memory for this desktop session and is not exported as observations. Switching projects, re-pairing, renderer navigation, suspend, quitting, or pressing **Stop demo** stops it. Hiding the workspace leaves the app and session running. Starting again creates another thread; it does not resume the earlier one. Closing or switching away can lose the in-memory conversation and draft. Native UI, a real Codex provider, and live account behavior require separate validation.
